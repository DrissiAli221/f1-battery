# F1 personal project: idea research

Date: 2026-10-17. Goal: an F1 project that is not one of thousands of clones,
built on a backend Java + cloud stack with a real Python/data component. All sources checked on 2026-10-17.

## Data sources (verified)

| Source | What it gives | Limits |
|---|---|---|
| [OpenF1](https://openf1.org/) | 18 endpoints: car_data (speed, throttle, brake, rpm, gear, ~3.7 Hz), location, intervals (4 s), laps, stints, pit, overtakes, race_control, team_radio (audio URLs), weather | Free: historical only, 2023+, 3 req/s, 30 req/min. Live needs €9.90/month. Team radio coverage "decreased significantly" in 2026 ([docs](https://openf1.org/docs/)) |
| [FastF1](https://docs.fastf1.dev/) (Python, v3.8.3) | Laps, telemetry, position, tyres, weather, results | Uses Jolpica for results/history |
| [Jolpica-F1](https://github.com/jolpica/jolpica-f1) | Ergast-compatible results/standings API, DB dumps | Small volunteer project, ~$45/month hosting |

**Key fact:** F1 decided not to publish active-aero or ERS (battery charge,
deploy, recharge) data for 2026. DRS is gone with no replacement. Maintainer
statement, 2026-03-14: [FastF1 discussion #861](https://github.com/theOehrly/Fast-F1/discussions/861).

## Saturated (avoid as the core)

- Race replay / live-timing apps: [f1-race-replay](https://gittrend.io/repo/IAmTomShaw/f1-race-replay) has ~6k stars; [undercut-f1](https://github.com/JustAman62/undercut-f1), f1-dash and others exist.
- Winner/podium prediction with ML: many repos (e.g. F1 Zoom, several Streamlit podium predictors).
- Tyre-degradation / pit what-if: already done by [F1-StratLab](https://huggingface.co/VforVitorio/f1-strategy-models), Armchair Strategist, an MCP strategy server, and others.
- Generic telemetry comparison dashboards.

## Less crowded angles

### A. Reverse-engineering the hidden 2026 battery (recommended)
Estimate each car's energy state (deploy, harvest, super-clipping) from public
telemetry, for every car and every 2026 race, then answer questions with it.

Prior work exists but is thin:
- [The Overcut substack](https://theovercut.substack.com/p/inside-f1s-2026-energy-war-reverse): rule-based regime model (deploy / brake harvest / lift-and-coast / super-clip / idle) on testing data. Single analysis, no code mentioned. Assumes 250 kW deploy and 8.5 MJ/lap.
- [f1-2026-lap-energy-simulator](https://github.com/Mahdi-Kadiri/f1-2026-lap-energy-simulator): single-car optimal-lap simulator, 0 stars. Doesn't infer real deployment.
- [f1-superclipping-viz](https://github.com/j5t3313/f1-superclipping-viz) (2 stars, qualifying visuals) and Tiwari1782/SPARC (0 stars, SoC estimate). Small repos.
- Media analyses: F1technical F1MATHS, PlanetF1 (Albert Park energy problem).

What would make it ours:
1. **Season-wide, all cars:** a pipeline over every 2026 race, not a single lap.
2. **Validated against something observable:** join the inferred battery state with OpenF1 `overtakes` and `intervals`. Testable question: is a car with low estimated charge more likely to be overtaken in the next N seconds? This turns a guess into a measured finding.
3. **Power-unit comparison:** Mercedes vs Ferrari vs Honda vs Audi vs Red Bull Ford customers, on clipping frequency and where on track it happens.
4. **Honest uncertainty:** publish what the model can't see (manual override, wind, fuel), as the Overcut analysis does.

Architecture: a Java/Spring Boot ingestion service + time-series store
(Postgres/TimescaleDB) + REST API. A Python inference module (FastF1 is
Python-native), plus a small web view. Data volume is real: ~3.7 Hz × 22 cars
× ~2 h per race, across the season.

Risks: rule constants were revised during the season (now verified, see the
section below; per-event limits vary). It's an estimate with no ground
truth, so it must be framed as such. Physics needs care.

### B. Team-radio intelligence
Transcribe radio (Whisper) and align each clip with race context. Then make it
searchable and classify it (box calls, strategy codes, battery/tyre complaints).
[f1radio](https://pypi.org/project/f1radio/) already adds context to clips, but its
transcription is "coming soon" per search results (page didn't load to confirm).
**Weakness:** OpenF1 says most 2026 events have no radio at all, so it works mainly for 2023–2025.
Could be a module of A (radio mentions of "battery"/"deploy" as weak validation) rather than a standalone project.

### C. Stewarding consistency dataset
FIA publishes decision PDFs with a consistent template (car, offence, decision,
reason). There is no structured public dataset. LLM extraction plus analysis of
consistency across steward panels and drivers.
Existing: 4 small 0-star repos ([GitHub search](https://github.com/search?q=f1+stewards+decisions&type=repositories)), mostly RAG chatbots.
**Weakness:** check fia.com terms/robots before scraping. Less fun, more legal/text work. RAG-over-regulations is becoming a common LLM demo.

## Recommendation

A is the strongest: new this season (only 2026 has these rules), the data is
hidden on purpose, few people have done it seriously, and the result is a
measurable finding. It's backend + data + a bit of Python, and the one-line summary is clear:
"F1 hides the battery data, so it is rebuilt from speed traces and checked
against overtakes." Optional later add-on: B as
weak validation, on 2023–2025-style radio where it exists.

## 2026 energy rules: verified from the primary FIA text

Source: [FIA 2026 F1 Regulations, Section C (Technical), Issue 20, 2026-08-05](https://api.fia.com/system/files/documents/fia_2026_f1_regulations_-_section_c_technical_-_iss_20_-_2026-08-05.pdf),
Article C5.2. Extracted locally with pdftotext. Check whether a newer issue
exists before modelling.

- **C5.2.7:** ERS-K DC power at most 350 kW.
- **C5.2.8, propulsion power as a function of speed** (the key modelling gift):
  - No Overtake: P = 1800 − 5·v (kph) below 340 kph; 6900 − 20·v from 340 to 345; **0 at ≥345 kph**.
  - Overtake active: P = 7100 − 20·v below 355; **0 at ≥355 kph**.
  - Race/Sprint, specified sectors in power-limited periods: 250 kW below 310 kph, then the same taper.
- **C5.2.9:** usable battery window (max − min state of charge) at most **4 MJ**.
- **C5.2.10:** recharge at most **8.5 MJ per lap**. May be cut to 7 MJ at some events. Qualifying can be cut further: the redline text reads "no less than 5 4MJ", so the exact floor is ambiguous. **+0.5 MJ** extra per lap is possible under B7.2 conditions. No limit behind the safety car in low grip.
- **C5.2.3:** fuel energy flow at most 3000 MJ/h.
- **C5.12.4–C5.12.7:** limits on how fast power can be reduced (50 or 100 kW per second, total 700 kW). This constrains what a real super-clip looks like in the speed trace.

In-season change (secondary source, agreed 2026-04-20, applied from Miami):
qualifying recharge 8→7 MJ, super-clip recharge power 250→350 kW, race MGU-K
350 kW in acceleration zones and 250 kW elsewhere. Source: [The Race](https://www.the-race.com/formula-1/f1-2026-mid-season-rule-changes/).
This is consistent with C5.2.8.iii above.

Why this matters: deploy power is a **known function of speed**, the battery
window is a known 4 MJ, and harvest per lap has a known cap. So the model is
constrained physics, not guessed constants. The Overcut's "constant 250 kW"
assumption is too crude. Hypothesis to test (not a fact): sustained powered
acceleration above 345 kph may indicate Overtake mode, but slipstream can also
explain it.

## Data availability check (queried OpenF1 directly, 2026-10-17)

- 2026 calendar in OpenF1: 25 races, 6 sprints. **17 races already have data**
  (Melbourne → Singapore, 2026-10-11). Bahrain (11261) and Jeddah (11269) return 404.
  Remaining races (Austin onward) add data as the season continues.
- Every race with data: 20–22 drivers, ~900–1,450 laps, 123–505 `overtakes` rows
  (these include pit and penalty position changes, so filter them).
- Telemetry quality (car_data, driver 1, race window only): Monza 3.71 Hz,
  Singapore 3.79 Hz, **no gaps over 2 s**, about 24k samples per car per race.
  Location data has a similar count. Monza top speed 350 kph (above the 345 kph
  no-Overtake cutoff).
- 2026 grid: 11 teams including Audi and Cadillac.
- Rough volume: 17 races × 22 cars × ~24k ≈ **9M telemetry rows**, plus about the
  same for location. Qualifying sessions add more and are the cleanest for
  clipping, since cars are flat out. Fetch cost: about 750 requests for race
  car_data + location. At the free 30 req/min that's about 25 minutes, once.
- Honest limits: 3.7 Hz means ~22 m between samples at 300 kph, so acceleration
  is noisy. A 2–4 s super-clip is only 7–15 samples, so it needs smoothing and
  a multi-lap baseline. There's no ground truth for battery state, so validate
  indirectly (overtakes, the C5.2.8 speed taper, radio where it exists).

Decision: A, recorded as D1.
